## Lessons learned

- The `sdlc milestone-close` boundary review runs in a subagent whose Bash can
  be broken (EPERM on `~/.claude/session-env`); it then can't run the suite and
  drops to static analysis (confidence: medium) and **demands the main agent run
  `go build ./... && go test ./cmd/sdlc/... ./pkg/vocab/`**. Always run it and
  record green in the close bundle.
- Dogfooding surfaced a real interaction: once discovery finds the *local*
  `workshop/projects` project, every milestone close of a project-tracked issue
  hits the per-milestone detail-block requirement. `--no-project` is the right
  answer when the project tracks at issue granularity.
- Removing a superseded function (`FindByIssueRef`) cascades to unused imports
  (`os`, `path/filepath`) in the file and its test — the build/vet is the guide;
  fix imports in both.
