# weave — intent compiler for layer composition (replaces construct/setup.sh)

## Problem

`construct/setup.sh` began as a run-once repo bootstrapper and has grown into the de-facto compiler that wires every ariadne-derived repo's agentic context. Three problems:

1. **Wrong altitude.** It's a bash interpreter of *file-ops* (`symlink X Y`) when what we want is a compiler of *intents* (`prose`, `skill`, `settings`, …). Structured composition — DAG resolution, JSON merge, multi-target codegen — strains bash, already evidenced by the separate `merge-settings.sh` and the bolted-on `discover-ancestors.test.sh` seam.
2. **Known bugs.** (a) Layer dependencies are partly carried by `go.mod` `replace` — the nous→brain *layer* edge lives in `go.mod`, not `construct/deps` (a constant source of confusion). (b) `@AGENTS.local.md` resolves through the symlinked `AGENTS.md` to *ariadne's* copy, so a downstream repo's own local prose never loads — every repo silently inherits ariadne's "you're in ariadne" note.
3. **Misleading name.** "setup" implies run-once; it's idempotent and should run on every layer/prose change.

## Spec

Replace `construct/setup.sh` with **`cmd/weave`** (Go, ariadne-owned) — a clean-sheet rewrite informed by 1000+ changes of experience, **not** a strangler port. Named `weave` for Ariadne's thread: it braids per-layer strands into one fabric.

**weave is dual-natured:**
- *Build-time compiler* — lowers each layer's declared **intents** into the target harness's runtime artifacts.
- *Run-time skill server* — `weave skills` (menu) / `weave skill <name>` (body) serve agent skills directly over shell, with no reliance on `.claude/skills/` discovery.

**Intent vocabulary** — a **hybrid** (the real `base.manifest` is ~all generic infrastructure verbs): weave **ports the existing file-op verbs** (`symlink`, `seed`, `scaffold`, `touch`, `merge`, `tool`) and **adds new semantic intents** (`prose`, `skill`). `merge` *is* the settings cascade; `prose` replaces the `@AGENTS.local.md` @-import; `skill` unifies the `sync-local-skills.sh` hook + per-layer skill symlinks. So #95 *adds* semantic intents atop the ported file-ops — it does not replace file-ops wholesale.

**Uniform lowering model.** weave lowers *every* intent per backend; intents differ only in **backend coverage** — not in kind:
- `prose` → composed into the harness system-prompt file (`AGENTS.md`). **Universal.**
- `skill` → served by weave itself; menu (names+descriptions) compiled into `AGENTS.md` for always-on discovery, bodies via `weave skill <name>`. **Universal** (weave supplies the mechanism).
- `settings` → **passthrough** to the harness's own config surface (Claude `settings.json` today). The one intent weave *cannot* universalize, because shell-tightness knobs (permissions/hooks/approval) are intrinsically per-harness. Thin portable core (env, coarse approval) + per-backend passthrough for the rich controls. **Narrowest coverage.**
- `scaffold` → directory conventions (`workshop/`, `atlas/`, …).
- `tool` → Go-binary ownership / build-in-owner wiring.

**Dependency & resolution.**
- Layer edges come **solely** from `construct/deps`; weave never infers them from `go.mod` or `go list -m all`. A build-necessary `replace` **stays**; a discovery-only one is **migrated**. (Verified: brain's `replace nous` is vestigial *for the Go build* but **load-bearing for layer discovery** — it's the sole current source of the nous→brain edge, since brain's `construct/deps` names only ariadne. So removing it is a required edge-preserving migration: add `substrate ../nous` first, then drop the `replace`.)
- Transitive resolution: topo-sort foundation-first, dedup (each layer applied exactly once).
- **Diamonds are free**: clone-as-peer + symlink means one on-disk copy per layer, so a diamond D→{B,C}→A collapses to "apply each layer once." **No versioning** — deliberate trade: single copy = single version; can't run repo D on old-A while E is on new-A (that'd need vendoring, out of scope).

**Cascade / collision semantics** (diamonds surface collisions, not version skew):
- `prose` → additive, concatenated foundation-first.
- `settings` → deep-merge, specific-wins.
- `skill`/files → namespaced (`xx-`/`nous-`/`metis-`) so they structurally can't collide.
- Suppressing an inherited fragment → deferred to v2; v1 is additive-only.

**Scope (v1).**
- Build the **`AGENTS.md` floor backend** + a clean backend-interface seam. Defer `.claude/rules` and native-skill backends. `settings.json` is v1's lone non-floor backend output (kept because it's load-bearing today — and it's the seam's first real client).
- Floor primitives assumed: a **system prompt + shell**. No `.claude/` assumptions anywhere in the core.
- **Symlink-only**; drop vendor mode (retire the stale `.ariadne-mode` marker).
- A thin shell bootstrap stub (the existing `bootstrap.sh`) builds + invokes `weave`.

**Open design details** (resolve in the plan): exact skill-menu placement (lean: descriptions compiled into `AGENTS.md`, bodies on demand); the extent of the portable settings core.

## Done when

- `cmd/weave` (Go) replaces `construct/setup.sh`; bootstrap/refresh invoke it; idempotent + re-runnable on any layer/prose change.
- **Golden-diff gate:** weave's output is diffed against `setup.sh`'s on the live repos (ariadne, nous, brain, metis); *every* divergence is accounted for in a reviewed ledger as an intended fix or a regression-then-fixed — **not** byte-equality (the current output contains the bugs above).
- A **fresh session** in a downstream repo (e.g. brain) loads *that repo's own* local prose, not ariadne's.
- Layer deps resolve **solely** from `construct/deps` (brain carries explicit `substrate ../nous`); `go.mod` no longer drives layer discovery.
- `weave skills` / `weave skill <name>` serve skills agent-agnostically (no `.claude/skills/` dependency).
- `settings.json` is still produced correctly for the Claude backend.
- Vendor mode removed; symlink-only.
- Tests: intent lowering, topo-sort + dedup (incl. a diamond fixture), cascade/merge semantics, and the golden-diff harness.
