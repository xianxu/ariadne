# Remove the `close --milestone` No-Review Bypass — Implementation Plan

> **For agentic workers:** Consult AGENTS.md Section 3 (Subagent Strategy) to determine the appropriate execution approach: use superpowers-subagent-driven-development (if subagents are suitable per AGENTS.md) or superpowers-executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove `--milestone` from `sdlc close`'s public surface so it can no longer perform a silent no-review milestone close, and fix the actual/verified re-run hints that misdirect agents to that path — leaving `sdlc milestone-close` (reviewed) / `--no-judge` (labeled skip) as the only ways to close a milestone.

**Architecture:** `sdlc close --milestone Mx` and `sdlc milestone-close` share the mechanical close body (`runClose`); only `milestone-close` dispatches the mandatory fresh-context review. `close --milestone` short-circuits before it (`close.go:785`). The mechanical `runClose(Milestone=…)` path stays — `milestone-close` calls it in-process. We only remove the *CLI flag* on `close` (hide it + refuse with a redirect), and repoint the two re-run hints via a small extracted `closeVerb` helper.

**Tech Stack:** Go 1.26, cobra.

**Architecture principles applied (`sdlc arch-principles`):**
- **ARCH-DRY** — `close --milestone` is a redundant second spelling of the already-labeled `milestone-close --no-judge`; removing it kills the duplicate footgun. The mode→verb selection (inline at `close.go:868-871`) is extracted into one `closeVerb` helper reused by both hint functions + `reviewThenFinalize`, instead of a third/fourth copy.
- **ARCH-PURPOSE** — the issue's purpose is "the innocent bypass can't be taken by accident." That has THREE parts, all shipped here: the flag itself; the two hints that actively point at it; AND the composed entry files (`CLAUDE.md`/`AGENTS.md`/`GEMINI.md`) that advertise `[--milestone Mx]` — regenerated from `AGENTS.base.md` via `make weave`, else this repo's own agent-facing docs keep showing the removed flag (plan-quality finding — shadow-sweep the *derived* doc consumers, not just the source).
- **ARCH-PURE** — `closeVerb` is a pure function (string→string), unit-tested directly; the refusal is a thin IO guard in the cobra path.

## Scope / blast radius

- **`runClose(Milestone=…)` in-process path is UNTOUCHED.** `milestone-close` builds its own `closeFlags` and calls `runClose` directly (`milestoneclose.go:104-179`, via `computeClose`/`reviewThenFinalize` — NOT via `runCloseWithReview`), so its mechanical close + review keep working. `close_ledger_test.go` (sets `Milestone:` and calls `shouldLogCalibration`/`runClose`-adjacent helpers) is unaffected.
- **ONE existing test breaks by design and must be repurposed:** `TestRunCloseWithReview_MilestoneClose_DoesNotDispatch` (`closereview_test.go:253-267`) calls `runCloseWithReview` **directly** with `Milestone:"M1"` and asserts success + zero dispatch — it guards the exact short-circuit Task 3 removes. It is the last caller (besides the cobra path) driving a milestone through `runCloseWithReview`. Task 3 repurposes it into a refusal assertion (see Task 3 Step 3b). The other `runCloseWithReview` test call sites (`closereview_test.go:108,198,220,280`) set no `Milestone` and are genuinely unaffected.
- **Base-layer doc + composed consumers.** `AGENTS.base.md` is `export` in `construct/base.manifest` — it flows into every derivative's composed `AGENTS.md` (downstream), AND weave composes it into THIS repo's `CLAUDE.md`/`AGENTS.md`/`GEMINI.md` entry files. Those three are **gitignored** (`.gitignore:22-24`) generated artifacts — regenerated by `make weave`, never committed. So editing `AGENTS.base.md` alone leaves the stale `[--milestone Mx]` in the working-tree entry files that every agent in this repo reads each turn (incl. this session) until `make weave` runs. Task 4 runs it; there is nothing to commit for the three (gitignored), but the recompose is required to actually deliver the purpose here.
- **Not touched:** the `--no-*`/`--force` conventions (already self-labeling); the `milestone-close` verb; `runClose`/`computeClose`/`applyClose`.

## Core concepts

### Pure entities

| Name | Lives in | Status |
|------|----------|--------|
| `closeVerb(milestone string) string` | `cmd/sdlc/close.go` | new |

- **`closeVerb`** — returns `"sdlc milestone-close"` when `milestone != ""`, else `"sdlc close"`. The single source of the mode→verb mapping.

In `runCloseWithReview` (~781-787) replace the short-circuit. **Use a returnable error, NOT `die()`** — `die` calls `os.Exit(1)` (`term.go`), which would kill the test binary before `cmd.Execute()` returns, so the Step-1 test couldn't assert. `runCloseWithReview` already returns `error` and the command runs under `SilenceErrors: true` with `main.go:47-49` printing `Error: <err>` + exiting — the soft-error pattern (`push.go`). So:
```go
// #146: `sdlc close --milestone` was a redundant no-review milestone close (it
// skipped the boundary review milestone-close dispatches). Removed from the public
// surface: refuse with a redirect. The mechanical milestone close still lives in
// runClose(Milestone=…), which milestone-close calls in-process (unaffected).
if f.Milestone != "" {
	return fmt.Errorf(
		"`sdlc close` no longer closes milestones (it would skip the boundary review).\n"+
			"  reviewed:       sdlc milestone-close --issue %d --milestone %s\n"+
			"  explicit skip:  sdlc milestone-close --issue %d --milestone %s --no-judge",
		f.Issue, f.Milestone, f.Issue, f.Milestone)
}
```
The refusal sits at the TOP of `runCloseWithReview`, before `computeClose` — so it fires before any issue-existence check (resolves the Task 5 ordering worry), and milestone-close is untouched (it calls `runClose` directly, never `runCloseWithReview`).

- [ ] **Step 3b: Repurpose the now-obsolete guard test.** `TestRunCloseWithReview_MilestoneClose_DoesNotDispatch` (`closereview_test.go:253-267`) asserts the OLD behavior (`runCloseWithReview` with `Milestone:"M1"` succeeds + doesn't dispatch).
