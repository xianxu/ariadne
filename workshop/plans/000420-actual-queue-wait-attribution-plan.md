# Queue wait attribution implementation plan

> **For agentic workers:** Consult AGENTS.md §3 for execution. Use test-first steps, commit each verified unit, and let `sdlc change-code` and `sdlc close` own the plan and code reviews.

**Goal:** Stop recorded machine-suite queue waits from becoming focused development hours; exclude samples with overlapping non-poll calls rather than estimating their work.

**Architecture:** Resolve validated suite attempts against the issue's pinned ownership history, retain the selected queue evidence with the measurement inputs, and pass source-scoped exact queue intervals to the native active-time engine. The engine rejects a sample if the waiting slot dispatched a non-poll tool call inside an interval; otherwise it subtracts the whole interval from that slot's attributed activity. The existing phase split runs on the corrected segments, so build, converge and tail all use one measurement.

**Tech stack:** Go; `cmd/sdlc` measurement and suite-attempt readers; `internal/activetime`; native JSONL transcript fixtures; `gatestate.MeasurementInputs` retained by close/correction.

## Core concepts

| Pure entity | Lives in | Status |
|---|---|---|
| `QueueInterval` | `cmd/sdlc/internal/activetime/queue.go` | new |
| `QueueAttribution` | `cmd/sdlc/internal/activetime/queue.go` | new |
| `MeasurementQueueWait` | `cmd/sdlc/internal/gatestate/measurement.go` | new |

`QueueInterval` is a half-open measured wait with attempt ID, owning slot, source binding and exact recorded seconds. `subtractQueueIdle(runs, waits)` removes the union of each source's queue overlap without restoring minutes from tool results. Its property tests use overlapping, duplicated and clipped intervals, asserting nonnegative minutes and source isolation. Multiple attempts belong to one measurement, and one attempt belongs to at most one pinned engagement. `MeasurementQueueWait` records the selected facts and record digest so replay cannot silently adopt a different set after the 30-day attempt retention expires (ARCH-DRY, ARCH-PURE, ARCH-ORDER).

Selection reads only validated published attempt records, with a bounded reader. It admits `check=suite` on this repository and an owning slot during a matching engagement; it clips to the measurement window and rejects ambiguous cross-issue or duplicate evidence rather than guessing. The suite record supplies the duration. For old records, `started_at - queue_seconds` through `started_at` is the reproducible interval convention, but `started_at` follows post-lock setup: this shifts the window late, leaves that setup-sized interval at the head of the actual wait counted, and excludes the same amount of setup near the run. Test that bias explicitly; do not claim exact window endpoints for legacy data. New records retain the actual queue start and acquisition timestamps. Missing queue data stays unknown and emits a bounded warning, never a fabricated zero. The existing reader is the sole validation boundary (ARCH-SECURE, ARCH-DRY).

`queueToolCallsFromTranscript` reads structural call dispatch timestamps only. Empty-input `write_stdin`, `wait` and recognizable native poll wrappers are polls; interactive input and all other tool calls are non-polls. A non-poll call inside a selected interval, or an admitted task span crossing it, refuses the sample as `overlapping work, unmeasured`. The enclosing suite call starts before `queued_at`; its later result is irrelevant. `bindQueueSources` maps the attempt's pinned slot to admitted source activity; the engine subtracts the full interval from those runs while leaving foreign slots unchanged. Unknown source ownership refuses correction. Results, call IDs and yielded-session pairing play no part in queue attribution (ARCH-PURPOSE, ARCH-ORDER, ARCH-SECURE).

`SuiteAttempt` keeps schema version 1 for compatibility and adds optional `queued_at` and `acquired_at` UTC timestamps as an all-or-none pair. The recorder takes `queued_at` at the existing `queueStart` and `acquired_at` immediately after `acquireSuiteSlot` returns, deriving `queue_seconds` from the same two instants. `decodeSuiteAttempt` admits old records with neither endpoint and rejects only-one-endpoint, reversed/future endpoints, `acquired_at > started_at`, or a timestamp difference inconsistent with `queue_seconds` beyond serialization precision. The reader prefers the exact pair; the documented late-shift convention applies only to old records. A stateful recorder test checks the queued/acquired/run-start ordering and a decoder test checks malformed endpoints (ARCH-SECURE).

Ordinary `sdlc actual` on a completed issue continues to replay the retained measurement generation unchanged, including old snapshots without queue evidence. Add `actualCorrectionCandidate` as an explicit measurement purpose for `sdlc issue correct-actual`: it is bound to that completion's code head, tracker head, source prefixes/windows and phase cuts, but selects currently available validated queue attempts and pins them into a new queue-aware snapshot. It refuses if those records or source bindings are incomplete; it cannot silently reinterpret an old adopted value. After a successful correction, ordinary historical reads replay the corrected snapshot. #416 therefore gets a fresh generation-bound correction measurement, not a changed historical display; if its attempts or transcript evidence cannot support it, the TL/operator excludes the sample through the existing correction verb (ARCH-PURPOSE, ARCH-ORDER).

No new long-lived files: the recorder already creates attempt JSON and prunes it at 30 days. Only a compact selected-evidence array grows in the existing bounded measurement snapshot, which remains attached to its completed issue/correction and is archived by the current flow (ARCH-FUNERAL, ARCH-CONSTRAINTS).

## Revisions

- 2026-10-17 — TL rejected the preceding result-decoder proposal after four close-review rounds on overlapping-work credit. Current design: select only the existing exact `queued_at`/`acquired_at` evidence; map each interval to the owning slot's admitted sources; scan structurally timestamped tool *calls* only. Poll calls are inert. A non-poll call dispatched inside `[queued_at, acquired_at)` refuses the sample as `overlapping work, unmeasured`; there is no result parsing and no restoration of queue minutes. The enclosing local-check invocation begins before its own queue interval, so it is not overlapping work. Without such a call, subtract the full interval from every mapped source's activity, preserving other slots and the existing phase split. Legacy attempts without exact endpoints stay unknown; #416 and #420 remain excluded rather than assigned replacement hours. Test first with a long polled queue, an overlapping edit/stage call, the enclosing suite call, multi-source ownership, foreign slot, interval clipping and retained replay. The simplest blanket subtraction without call detection fails to flag genuine overlapping work; a result decoder is more complex and has repeatedly credited unproved time. Supersedes the prior Revision and work-crediting task prose below (ARCH-PURPOSE, ARCH-ORDER, ARCH-SECURE).
- 2026-10-17 — Close review round 4 kept BR-2 open on Claude result envelopes even after poll-derived queue binding was removed. Before work-span attribution, normalize every supported native result into `terminal` or `uncertain` using one decoder, retaining tool-level `is_error`. For Claude, decode a string or text-block array rather than passing raw JSON bytes; `is_error`, empty text, transport errors, unknown-process text, malformed or unrecognized content are uncertain. For Codex, decode scalar strings and text-block arrays by the same rule; an object with numeric `exit_code` is terminal, while a session/cell ID without exit is yielded and other unrecognized objects are uncertain. Only a direct allowlisted work call with a unique ID and terminal result yields positive work. A wait or poll never does; incomplete and duplicate work remains uncertainty. Add cross-harness parser tests for each envelope and a production `Compute` regression where a Claude error result overlaps an exact recorded queue and must refuse rather than restore minutes. This is outcome normalization within the approved exact-record design, not a return to poll pairing (ARCH-DRY, ARCH-PURPOSE, ARCH-SECURE, ARCH-ORDER).
- 2026-10-17 — Re-plan after the third close-review finding in poll pairing; TL approved. The simplest alternative is to stop deriving queue duration or completion from transcript polls. New local-check attempts already record exact `queued_at` and `acquired_at`; select those only when the attempt is pinned to this issue's slot and engagement. Apply the recorded interval to every admitted activity source mapped to that slot during the interval, retaining independently timestamped, directly paired non-yielded work calls and admitted task spans. A source without unique slot ownership is an evidence gap, not a guessed match. This removes the enclosing-suite invocation and all poll/session call-ID transitions from queue binding. A yielded work command overlapping queue time has no proven end without its polls, so refuse that measurement as incomplete rather than count or silently discard it. The yielded `sdlc local-check run` invocation is a wait, never uncertain work; test this exact case. Legacy attempts without both exact endpoints remain unknown and make the sample ineligible for calibration; do not reconstruct a shifted window from `started_at - queue_seconds` for corrected hours. Retain the exact attempts, source/slot mapping, work spans and uncertainty reason in replay inputs. Tests: duplicate/reused IDs cannot restore work; multiple owned sources are clipped once each; foreign/ambiguous sources are never subtracted; overlapping direct work survives; yielded work and legacy-only attempts produce explicit incomplete evidence; a recorded new attempt replays without ambient files. Blanket subtraction of `queue_seconds` is simpler still but fails the Spec's staged-work overlap, so interval subtraction with independent work evidence remains necessary (ARCH-PURPOSE, ARCH-ORDER, ARCH-SECURE).
