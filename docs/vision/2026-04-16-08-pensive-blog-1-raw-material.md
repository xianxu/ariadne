## The Week That Led to the Insight

### 1. Tool Calls in Parley (Issue #81, ~7K lines)

On a flight from Pittsburgh to SF last Thursday, I started writing tool call support into Parley — allowing it to read and write files. This opened the door to simple coding use cases: describe what you need, generate a script. I implemented `ls`, `grep`, read/write files. Easy enough to extend to bash commands, but I didn't go that far.

This was Parley's first step from "conversation tool" toward "harness."

### 1.1. The Multiplexed Stream Refactor (Issue #90, ~7K lines)

Tool calls introduced a new multiplexed stream, and AI made a mess packing it on top of old code where there was a single insertion point in a buffer. It was quite a struggle to stop the AI and articulate a proper model: **use the exchange model as the source of truth, as the intermediate representation. You are inserting into the exchange model at several different points, not directly inside a buffer.**

This was the most intensive human intervention in recent memory. The AI kept wanting to patch the old approach. I had to stop it, draw the boundary, and impose the architecture. Classic case of the human providing the structure, AI providing the labor.

Issues #81 and #90 together: tangled across 66 commits. Two days of steering. ~14K lines of change total. A pretty complex feature.

### 2. The Review Feature — Parley as Harness

The main purpose of tool calls was to enable a review feature for my writing. This was the first time Parley acted like a **harness** — not just a conversation tool, but an environment that runs a structured AI loop.

The integration with Neovim was natural and powerful:
- Changes shown with different colors (diff highlighting)
- Edits needing human attention surfaced in Neovim's quickfix list
- Editorial notes displayed through Neovim's diagnostic system

An interesting realization here: there are different ways to structure an LLM loop. In this case, we have a document with custom markup indicating multiple turns between user and AI:

```
㊷[user makes a comment about some paragraph]{AI might ask for clarification}[user clarifies again]
```

The document IS the conversation. The loop runs on the document, not in a chat window. This is fundamentally different from how Claude Code's loops work — and that difference matters.

While all this was building up, the thoughts around the pitch deck and Ariadne started forming. That's when the Ariadne repo began.

### 3. The Construct — Meta-Tool for Skill Evolution

Built `/construct`, a meta-tool that organizes skills for a local repo. The best way to describe it: a structured way to evolve skills. You have upstream skills like superpowers, you have your own philosophy described in `AGENTS.md` and other intention files, and you combine them to create a version of superpowers tailored for your repository — with your own branching strategy, directory structure, and workflow.

This led to experimenting with "semantic merge" — how to do meta-programming in a stochastic world. How do you take someone else's skill and adapt it to your context without brittle text patching? The answer: store the intent (the conversation that produced the adaptation), not the patch.

After building the Construct, I adapted the superpowers skill into the Parley repo, making it work harmoniously with Parley's design philosophy. The Construct made this possible in a structured, repeatable way.

### 4. Skills: Voice, Critic, Interview Feedback

Created a batch of skills in Ariadne:

**Voice adaptation** — extremely simple to create. Sent Claude 40 of my blog posts, asked it to generate instructions for adapting AI-generated writing to my style. The result: a style guide that drives `/xx-voice-apply`.

Here I realized the similarity between "review" and "critic" — it depends on the starting position of the writing:
- If I (as human) wrote it mostly to publishable quality → AI does minor edits (review mode)
- If a document starts with my vague ideas but was generated by AI → applying my voice matters so it doesn't read like AI slop

I spent quite some time iteratively adapting the voice skill to my actual tone. Not a one-shot thing — many rounds of "no, that's not how I'd say it."

**Interview feedback** — builds on Parley's interview mode, generates structured feedback from my recorded `[questions]`, candidates' answers, and `{my thoughts about it}`. Again, spent time iteratively correcting the skill: don't mention candidate's name or sex, use generic TC and gender-neutral pronouns (e.g., "they"). A habit from my Meta days baked into a reusable workflow.

### 5. The Eureka: Single State, Multiple Harnesses

All of this led to a realization: the "skills" are shareable across different harnesses. The system prompt I used in Parley's review tool can be shared with skills in Claude Code. So why not create a skill system in Parley too?

The difference between Parley's skills and Claude Code's skills isn't the skill itself — it's the operating environment and UX:
- In the Neovim world, you're in a text editor with IDE-like extensions. The interaction is document-centric, visual, integrated with quickfix and diagnostics.
- In Claude Code, you're in a terminal. The interaction is conversation-centric, execution-oriented, with tool calls and file operations.

**What's important: both operate on exactly the same state — the filesystem.** Each provides different ways for the user to interact with the harness, in ways natural for that particular task.

**This is the eureka moment: single state, multiple harnesses.**

The state (your repo, your files, your accumulated context) is the real workspace. The harnesses are specialized lenses. You pick the right one for the job. And because they share state, work done in one is immediately available to the other.

## Narrative Arc for Blog Post 1

The progression:
1. **Tool calls** — Parley gains the ability to act on files (flight hack)
2. **Refactor struggle** — the human imposes architecture when AI can't (the exchange model insight)
3. **Review feature** — Parley becomes a harness, not just a tool (document-centric AI loops)
4. **The Construct** — skills become portable, adaptable (meta-programming in a stochastic world)
5. **Voice/critic/interview skills** — the skills multiply, each with iterative human correction
6. **The eureka** — skills are shareable because the state is shared. Single state, multiple harnesses.

Each step is bigger than the last. Each one is grounded in a specific thing I built. The insight emerges from the accumulation — it wasn't planned, it was discovered.
