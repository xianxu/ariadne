Slide 2: Problem

Have you tried using AI for real work — not a demo, but actual production problems?

It doesn’t get solved in one shot. Your language is imprecise, the domain understanding is patchy, and requirements shift as you build. You discover new potentials and constraints along the way. The workflow of a knowledge worker is living and evolving.

Effective AI use is a search problem. You’re narrowing infinite possibilities down to a concrete outcome, through a series of interactions, using a stochastic machine, aka LLM. Nobody has built the tools to make that search sustainable yet.

Slide 3: Insight

LLMs are a new stochastic OS. The native application layer hasn’t been built.

LLMs are the next platform — a stochastic OS that can execute cognitive tasks and processes, plausibly. The application layer race starts now. That’s the race of the harnesses.

The AI-first workflow looks fundamentally different:

  • AI runs the process loops, humans steer
  • The human provides both the structure (how loops work) and the content (judgment, context, choices) — think managers, not operators
  • Workflows evolve through use — living structures, not static templates
  • And a natural way for humans to define what is correct, not just what’s plausible (the “vibe coding” problem)

Slide 4: Solution — Ariadne

The gap isn’t intelligence. It’s the ability to steer. And doing so sustainably.

Think AlphaZero — it works because it learns a board evaluation function through self-play. In knowledge work, there aren’t going to be enough training examples. The human is the evaluation function, and we need to make that sustainable.

Ariadne unifies what today’s tools keep separate — the AI loop, the domain state, and the workflow knowledge — into one environment the human can actually shape:

  • Repo as world state. Every “shot” is a state change, not a chat reply. Every human edit is an evaluation signal.
  • Structured checkpoints. Surface decisions where human judgment matters most — the right moments, the right granularity.
  • Living workflow. Patterns the human can inspect, edit, and evolve. The system adapts through use; the human architects the structure.
  • Persistent, editable history. Transparent and replayable. Change a past decision, re-converge from there.

Slide 5: What I’ve Built

I’ve been building and using the harness daily.

  • A working Nvim-based environment: AI runs tool loops, human express intent, the repo holds all state, I steer through editable transcripts, living workflows, branching conversations, and persistent memory.
  • The entire workflow — brainstorming, architecture, coding, roadmapping, issue tracking, spec writing — runs through the harness. This pitch deck was created in it.
  • The key insight from using it: the leverage isn’t in any single AI response. It’s in the accumulation — skills that remember how you work, the continuous tweaking of the process itself, the state that persists across sessions, the ability to re-converge when requirements change.

Slide 6: Roadmap — From Nvim to Universal

Phase 1: Developer harness (now)

  • An opinionated Neovim-based environment where the repo is the world state, markdown manages workflow, and AI loops are steered through skills, issues, and specs.
  • Prove the thesis by building the company itself with the harness. If it can’t do that, it can’t do anything.
  • Immediately usable for other technical founders.

Phase 2: Standalone cockpit

  • Same convergence engine, same living workflow — but multiple interfaces beyond Neovim. IDEs, web, desktop, collaborative.
  • Target: technical founders and small dev teams who want the paradigm without living in Nvim.

Phase 3: Universal harness

  • The convergence engine becomes a platform. Skill ecosystems for legal, consulting, product, operations. Those professions need different UX for them to manage and influence their own workflows.

Slide 7: Why Now

  • Capability just arrived. LLMs can now reliably execute multi-step cognitive tasks — just look at what coding agents can do today. Two years ago they couldn’t.
  • Tool use is maturing. Models call tools, execute code, interact with APIs. They’re loop executors now, not just text generators.
  • The window is open. The industry is in its “faster horse” phase — everyone is bolting AI onto existing workflows. Once someone demonstrates the native paradigm, the shift will be obvious in hindsight. That’s pretty much always how platform shifts work.

Slide 8: Market

  • Wedge: Programmers and technical founders. They feel the pain most acutely, can evaluate the product, and software is the most mature domain for AI tool use.
  • Expansion: All knowledge work — consulting, legal, product, operations. Any domain where work requires iterative refinement and human judgment.
  • This is not a tool market — it’s a platform shift. We won’t capture the whole market, but even a slice is pretty compelling.

Slide 9: Competition

vs. OpenClaw (open-source AI agent, 247K GitHub stars): OpenClaw is a task executor — “do this for me.” It automates well-defined tasks. Ariadne solves a different problem: convergence on ill-defined outcomes when you don’t know exactly what you want. OpenClaw is the faster horse. We’re building cars.

vs. Copilots (GitHub Copilot, Cursor, etc.): Code-level assistants bolted onto existing IDE workflows. They help you type faster. We restructure the loop so AI executes and humans steer.

vs. Agent frameworks (LangChain, CrewAI, etc.): Infrastructure for developers building AI apps. We’re building the end-user application — the cockpit — not the plumbing.

vs. Claude Code / Codex CLI: These operate at the code plane. We operate at the decision and convergence plane — a higher level. We use coding-plane agents underneath (and we use them heavily).

vs. Claude Co-Work: The strongest contender. They’re bringing AI-native workflows to a broad audience. The difference: we start from complex, real-world workflows and give users the ability to shape the workflow itself — inspect it, edit it, evolve it. Not just pick from templates.
